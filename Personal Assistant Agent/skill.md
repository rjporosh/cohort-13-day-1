# Skill: Personal Admin Sorting

Sort every task from admin-inbox.md into exactly one of these buckets:

- **Today**
- **This Week**
- **Waiting** (blocked on another person or missing info)
- **Study**
- **Family**
- **Money**
- **Later**

Note: a task can carry both a *timing* label (Today / This Week / Waiting / Later) and a *domain* label (Study / Family / Money) — e.g. "Scholarship form" is both Today/This Week AND Money-related. The output groups by timing first, then cross-references domain.

## For every task, record:

1. **Task name** — short, clear restatement
2. **Category** — timing bucket + domain tag(s)
3. **Priority** — High / Medium / Low, based on memory.md rules (money, deadline, health, family = highlight)
4. **Next action** — the single concrete next step
5. **Deadline if known** — exact day/time, or "not specified"
6. **Missing information if any** — what's unclear and needs the user to clarify

## Sorting logic (from memory.md)

- Anything with a hard deadline (bill, scholarship, submission) → High priority, never auto-moved to Later.
- Family tasks (health, errands for family members) → never ignored, always surfaced even if not urgent.
- Study tasks → prefer morning slots; never placed against class time.
- If exam week is flagged by the user, low-priority/non-deadline tasks shift to Later automatically.
- Anything waiting on another person's reply/action → Waiting, not Today, unless the user must also act today (e.g., send the reply).
